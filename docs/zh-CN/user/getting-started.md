# 快速开始

English: [../../en/user/getting-started.md](../../en/user/getting-started.md)

这份文档面向使用 Culvia 的摄影师，不是面向修改代码的开发者。

## 启动应用

从源码仓库启动：

```bash
make init
make server
```

只启动 Web server：

```bash
make web PORT=8501
bin/culvia-web --host 127.0.0.1 --port 8501
```

通过 pip 安装后，使用安装出的 console commands：

```bash
culvia-supervisor
culvia-web --host 127.0.0.1 --port 8501
```

## 基本流程

1. 选择本地照片目录，或上传临时照片。
2. 选择要运行的本地模型，按需启用大模型评审。
3. 开始评分，并查看当前照片和进度。
4. 在选片台或照片墙复核照片。
5. 标记人工判断：入选、待定、淘汰、星级和色标。
6. 导出入选照片或 CSV 结果。

取消评分或任务异常结束后，已完成的模型阶段仍会保留，并显示在照片结果中。使用相同来源和评分库重新评分时，会复用这些结果；也可以继续复核、导出，或按需运行大模型评审。刷新页面不会取消仍在后台运行的任务。

## 照片来源

目录模式下，来源编辑器是目录行列表。你可以逐条添加路径、把多行路径粘贴到追加输入框、编辑已有目录、复制完整路径，或删除某一行，不需要重写整段来源列表。Culvia 会展开 `~`、归一化目录路径，并在父目录已存在时移除冗余子目录，然后递归扫描子目录并按 canonical path 去重照片。

拖拽模式下，把文件夹拖入页面会递归导入其中支持的图片，作为临时上传来源使用。当前评分库是 SQLite 文件时，目录来源会在下次启动应用时恢复。

来源摘要将目录名与目录数、照片数分行显示。鼠标悬停或用键盘聚焦摘要时可查看完整路径；需要复制路径时，打开来源编辑器即可。

## 人工判断

人工判断是最终选片层。模型和大模型分数用于排序和解释，但不会覆盖你的入选/待定/淘汰判断。

- `入选`：进入交付或后续精修。
- `待定`：需要再复核一轮。
- `淘汰`：排除出最终集合。
- 星级和色标可用于后续 Lightroom/Capture One 风格工作流。

桌面宽度下，人工判断控件位于照片旁。紧凑布局下，控件紧接照片显示，随后才是胶片条和评分详情。分布视图的导航会自动换行，无需横向滚动即可找到所有视图。

## 大模型评审

大模型评审是可选功能。只有需要图片评价、细维度审美/技术分数、修图建议和拍摄建议时，才需要配置 OpenAI-compatible endpoint 和模型。API key 应通过应用配置/keychain 流程保存，不应写入 Git 或文档。

## 导出

交付候选照片时使用入选照片导出；需要评分证据、人工状态、色标和下游映射时使用 CSV 导出。详见 [导出工作流](export-workflows.md)。

## 版本与更新

打开 **设置 → 关于 Culvia**，可以查看当前为页面提供服务的版本、运行形态、平台和架构。桌面 Full 与 Desktop Lite 在桌面壳和 Python 服务版本不一致时，还会分别显示两个版本。

点击 **检查更新** 后，Culvia 才会查询官方 GitHub 仓库的最新正式发布；应用不会在后台自动检查，也不会自动下载或安装更新。发现新版本后，请从发布页面选择与当前平台及运行形态完全匹配的包，并在安装前核对校验和或 GitHub attestation。若该 Release 没有完全匹配的包，不要改装其他平台或运行形态的资产；请保留当前安装并查看发布说明中的可用性。Desktop Lite 若出现桌面壳与服务版本不一致，应先处理版本差异并重启应用，再使用新版本功能。
